# README

# Практическая работа №3: Реализация структурного паттерна «Адаптер» в C#

## Цель работы

Закрепить теоретические знания по теме «Структурные паттерны проектирования» и получить практические навыки реализации паттерна **«Адаптер» (Adapter)** в консольном приложении на языке C#.

## Описание проекта

Консольное приложение **«Система интеграции платёжных систем»**, демонстрирующее работу паттерна «Адаптер» для согласования несовместимых интерфейсов. Приложение позволяет работать с двумя разными платёжными системами — **старой (XML)** и **новой (JSON)** — через единый интерфейс `IPaymentProcessor`.

---

## Архитектура и структура классов

### 1. `IPaymentProcessor` — целевой интерфейс

Единый интерфейс, с которым работает клиентский код:

```csharp
void Pay(decimal amount, string purpose);
string GetPaymentInfo();
```

### 2. Несовместимые платёжные системы (адаптируемые классы)

| Класс | Формат данных | Метод |
|-------|---------------|-------|
| `OldPaymentSystem` | XML | `string? MakePaymentXml(string xmlData)` |
| `NewPaymentSystem` | JSON | `string? ProcessPaymentJson(string jsonData)` |

Каждая система:
- Десериализует входные данные (XML/JSON) в `PaymentDto`.
- Валидирует платёж через `Validate.Payment`.
- Генерирует `transactionId` (GUID) при успехе.
- Возвращает `null` при ошибке.

### 3. Классы-адаптеры

| Адаптер | Адаптируемая система | Формат |
|---------|---------------------|--------|
| `OldPaymentAdapter` | `OldPaymentSystem` | XML |
| `NewPaymentAdapter` | `NewPaymentSystem` | JSON |

Каждый адаптер:
- Реализует `IPaymentProcessor`.
- Хранит состояние последнего платежа (`_amount`, `_purpose`, `_transactionId`).
- В методе `Pay` сериализует `PaymentDto` в нужный формат и вызывает соответствующую систему.
- В `GetPaymentInfo` возвращает информацию о результате платежа.

### 4. `PaymentDto` — DTO платёжа

Общий класс данных с атрибутами сериализации:

```csharp
[JsonPropertyName("amount")]  [XmlElement("amount")]     public decimal Amount
[JsonPropertyName("purpose")] [XmlElement("purpose")]    public string? Purpose
[JsonPropertyName("currency")][XmlElement("currency")]   public string? Currency
```

### 5. `Validate` — статический класс валидации

Проверяет:
- `Amount > 0` и `Amount <= 1_000_000_000`.
- `Purpose` не пустое и не длиннее 200 символов.
- `Currency` не пустое.

### 6. `PaymentManager` — менеджер платежей

- Хранит список выполненных платежей (`List<string>`).
- `ProcessPayment(IPaymentProcessor processor, decimal amount, string purpose)` — выполняет платёж и сохраняет информацию.
- `ShowAllPayments()` — выводит все платежи с разделителями.
- `ClearAllPayments()` — очищает список.

### 7. `Print` — вспомогательный класс вывода

- `Introduction()` — главный экран.
- `Menu()` — интерактивное меню.

### 8. `Program` — точка входа

- Выводит информацию об авторах и работе.
- Запускает **демонстрацию паттерна** (`DemonstratePattern`).
- Реализует **интерактивное меню** из 5 пунктов.
- Вспомогательные методы `ReadAmount()` и `ReadPurpose()` с валидацией ввода и возможностью отмены (пустая строка).

## Функциональные возможности

### Главный экран (точка входа)

При запуске выводится:
- Фамилия и имя студентов.
- Название группы (9ИС-435).
- Название практической работы (ПР №3: Паттерн «Адаптер»).
- Краткое описание работы.

### Интерактивное меню

| № | Пункт меню | Действие |
|---|-----------|----------|
| **1** | Оплатить через старую систему | Создаёт `OldPaymentAdapter`, запрашивает сумму и назначение, выполняет платёж |
| **2** | Оплатить через новую систему | Создаёт `NewPaymentAdapter`, запрашивает сумму и назначение, выполняет платёж |
| **3** | Показать все платежи | Вызывает `ShowAllPayments()` |
| **4** | Очистить список платежей | Вызывает `ClearAllPayments()` |
| **5** | Выход | Завершает работу приложения |

### Подтверждение действий

После каждого платежа выводится сообщение с актуальным количеством:

```
Успешно! Всего платежей: 3
```

### Демонстрация работы паттерна

В методе `Main` отдельный блок `DemonstratePattern()`:
- Создаёт экземпляры `OldPaymentAdapter` и `NewPaymentAdapter`.
- Через переменные типа `IPaymentProcessor` выполняет по одному платежу каждым адаптером.
- Показывает тип переменной (`IPaymentProcessor`) и фактический тип (`OldPaymentAdapter` / `NewPaymentAdapter`).
- Демонстрирует, что клиентский код работает одинаково с разными системами.

## Дополнительные особенности реализации

- **Валидация ввода:** проверка суммы (`decimal.TryParse`, `> 0`, `<= 1_000_000_000`) и назначения (не пустое, `<= 200` символов).
- **Отмена ввода:** пустая строка отменяет платёж.
- **Замена точки на запятую:** поддержка десятичных разделителей (`input.Replace('.', ',')`).
- **Обработка исключений:** `try/catch` для `InvalidOperationException` (XML) и `JsonException` (JSON).
- **Единый DTO с двумя наборами атрибутов:** `PaymentDto` используется и для JSON, и для XML.
- **Класс `Validate`:** централизованная валидация платежа для обеих систем.
- **Генерация `transactionId`:** уникальный идентификатор через `Guid.NewGuid().ToString("N")`.
- **Разделители в выводе:** `ShowAllPayments` разделяет платежи линией.

## Используемые технологии и принципы

- **Язык:** C#
- **Платформа:** .NET (Console Application)
- **Паттерн:** Adapter (структурный)
- **Сериализация:** `System.Text.Json` (JSON), `System.Xml.Serialization` (XML)
- **Принципы ООП:** абстракция, инкапсуляция, полиморфизм
- **Принципы SOLID:**
  - *Single Responsibility* — каждый класс отвечает за свою задачу.
  - *Open/Closed* — новая платёжная система добавляется через новый адаптер без изменения клиентского кода.
  - *Liskov Substitution* — оба адаптера корректно подставляются вместо `IPaymentProcessor`.
  - *Dependency Inversion* — клиентский код (`PaymentManager`) зависит от интерфейса, а не от конкретных систем.
